## Playbook: Worth Testing

- **Aggressive firewall bot mitigation can strip critical SEO metadata and block search crawlers | 激进的防火墙防爬虫策略可能导致 SEO 元数据被剥离**  `P2` `Data-backed`
  - 为何重要 / Why: 在应对恶意 Bot 攻击时，运维团队常通过 CDN/防火墙（如 Cloudflare、AWS WAF）实施紧急限制。这可能导致服务器在过载时向爬虫返回剥离了 title、canonical、hreflang 和 schema 的简化版 HTML，或者直接误杀 Googlebot，导致索引量和排名暴跌。
  - 证据 / Evidence: practitioner_observation
  - 影响 / Affects: ecommerce / publisher / SaaS / UGC / all
  - 行动 / Action: 检查 CDN/WAF 的速率限制和 Bot 管理规则，确保在触发防御机制时不会向 Googlebot 返回受损的 HTML，并使用工具模拟不同 IP/User-Agent 进行验证。
  - 详情 / Detail: A case study of a large online marketplace revealed a severe SEO drop caused by firewall-level bot restrictions that stripped title tags, hreflang, canonicals, and schema across core page types during a bot attack. After upgrading servers, implementing robots.txt crawl delays for non-essential bots, and whitelisting search crawlers, indexation recovered from 250k to 600k pages.
  - 如何测试 / Test: 使用外部测试工具（如 SERP Lens 或自定义脚本）模拟 Googlebot，从不同区域的 IP 访问网站，特别是在高负载或触发防火墙规则时，检查返回的 HTML 中 title、canonical、hreflang 和 schema 是否完整，以及是否返回了 503 或 403 状态码。
  - 衡量 / Measure: 确保 Googlebot 在任何负载/防御状态下均能 100% 获取完整的 SEO 元数据和 200 OK 状态码，避免索引量异常波动。
  - 成本与风险 / Effort: 低成本。主要风险是运维团队在配置防火墙时未将 Googlebot/Bingbot 列入白名单，或在边缘计算（Edge Functions）中错误地剥离了元数据。
