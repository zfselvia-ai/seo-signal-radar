## Official Explanations

- **Google updates its generative-AI content guidance: 'critical to manually factcheck and review all AI-generated content' — titles, meta, schema and alt text included | Google 更新生成式 AI 内容指南：“发布前必须人工核查所有 AI 生成内容”，含标题、meta、结构化数据与 alt**  `P1` `Confirmed`
  - 为何重要 / Why: 措辞从“可以用 AI”变成“必须人工复核”，并直接引用质量评估指南 4.6.5（scaled content abuse）和 4.6.6（低投入/低原创）。这是在给无人监督的批量生成划线。
  - 证据 / Evidence: official doc: developers.google.com/search/docs/fundamentals/using-gen-ai-content (changelog Oct 1); verified against the live doc Oct 10
  - 影响 / Affects: all
  - 行动 / Action: 检查内容流程里 AI 生成的标题/meta/结构化数据/alt 是否有人工复核环节；没有的先补到发布 checklist，并抽样回查已发布页面的事实错误。
  - 详情 / Detail: The Search Central changelog for Oct 1, 2026 says the gen-AI guide was updated with information from the Search Quality Rater Guidelines. New text explains that models predict a likely sequence of words and 'may contain inaccuracies (also known as hallucinations)', and that it is critical to manually fact-check and review all AI-generated content — explicitly including title elements, meta descriptions, structured data and image alt text — before publishing. The doc cites QRG sections 4.6.5 and 4.6.6. Google frames this as syncing documentation with its developer-event talks and announces no ranking-system or policy change. Cited source: Search Engine Roundtable's report, retweeted by Dawn Anderson.

## Technical SEO Experiments

- **Merj: AI agents complete ~60% of 100 web tasks (up from ~30% in Nov 2025); a mislabeled ARIA button made ChatGPT Agent click Cancel 25/25 times | Merj：AI 代理在 100 项网页任务中成功率约 60%（去年 11 月约 30%）；ARIA 标签错误让 ChatGPT Agent 25 次全点了“取消”**  `P2` `Data-backed`
  - 为何重要 / Why: 代理式购买/预订正在变成真实流量来源，而它们失败的地方（canvas、纯图标按钮、GDPR 弹窗、表单可访问名称）就是可访问性问题。无障碍修复直接等于代理转化率。
  - 证据 / Evidence: research: 100 purpose-built tests + live pages, multiple agents, repeated runs, Nov 2025–Mar 2026 (Merj); shared by @screamingfrog
  - 影响 / Affects: ecommerce / SaaS / local
  - 行动 / Action: 用一个代理浏览器（ChatGPT Agent / Comet）跑完你站的核心任务（找商品→加购→结账或预约），记录卡点；优先修按钮可访问名称、去掉纯图标 CTA、让 cookie 弹窗可被键盘关闭。
  - 详情 / Detail: Merj built 100 test pages plus live production pages and ran multiple agents repeatedly over six months. Average task success rose from roughly 30% (Nov 2025) to 60% (Mar 2026); canvas apps (~24→34%), icon-only buttons (~34→45%) and GDPR banners (~50→64%) stayed weakest. In a mislabeled-ARIA test, ChatGPT Agent in Atlas clicked Cancel first in 25 of 25 runs while Claude Computer Use and Perplexity Comet hit Save 25/25. Merj does not publish the dataset, calls the values approximate, and sells agent-interaction monitoring; results are version-specific and already months old.

## Playbook: Worth Testing

- **Playbook: turning the plain-text brand label on product pages into a link to the brand PLP lifted PLP organic traffic +18% in a SearchPilot A/B test | 玩法：把商品页上的纯文本品牌名改成指向品牌品类页的链接，品类页自然流量 +18%（SearchPilot A/B 测试）**  `P2` `Data-backed`
  - 为何重要 / Why: 机制是全站一致的 PDP→品类页内链给爬虫更清晰的“商品归属集合”信号，等于用一处模板改动给品类页注入内链权重；成本极低，且商品页本身没有受损。
  - 证据 / Evidence: controlled SEO split test on one ecommerce site (SearchPilot case study, Demetria Spinrad)
  - 影响 / Affects: ecommerce
  - 行动 / Action: 在 PDP 模板里把品牌/品类文字改为指向对应 PLP 的链接，按页面桶做 50/50 分流测试 4 周以上，看 PLP 自然流量相对预测值的变化。
  - 详情 / Detail: SearchPilot ran a controlled split test on an unnamed ecommerce site: variant PDPs linked the brand name to the brand-level PLP, control PDPs kept plain text. Result: a predicted +18% organic traffic uplift to brand-level PLPs at a 95% credible interval, while PDP traffic itself was inconclusive (no harm detected). Not stated: number of pages, test duration, interval bounds, or whether more inbound links produce a bigger lift. SearchPilot sells the testing platform.
  - 如何测试 / Test: PDP 模板：品牌/品类名文本 → 链接到对应 PLP；对照组保持纯文本；跑 4–6 周，对比 PLP 自然点击/会话与预测基线。
  - 衡量 / Measure: 品牌/品类 PLP 的自然流量相对预测值的提升（SearchPilot 得到 +18%，95% 可信区间），且 PDP 不下降。
  - 成本与风险 / Effort: 低：一处模板改动；风险是内链稀释或 PDP 受影响（本案例未见），以及案例由卖测试工具的供应商发布。

## Tools, Papers & Open Source

- **Lighthouse 13.5 adds an 'Agent Resource Discovery' audit checking robots.txt Agentmap, <link rel=ai-catalog> and /.well-known/ai-catalog.json | Lighthouse 13.5 新增“代理资源发现”审计，检查 robots.txt Agentmap、ai-catalog link 与 well-known 文件**  `P3` `Confirmed`
  - 为何重要 / Why: Google 的工具链开始检查面向 AI 代理的站点声明，说明 ARD/llms.txt 一类标准在被正式对待；但它不与搜索排名挂钩，目前只是“有没有、格式对不对”。
  - 证据 / Evidence: release: Lighthouse v13.5.0 (PR #17168), reported by SEJ and the SEOFOMO newsletter (via @dawnieando RT)
  - 影响 / Affects: all
  - 行动 / Action: 暂不动；如果已经维护 llms.txt，可顺手发布一个 ai-catalog.json 并用 Lighthouse 13.5 验证格式，作为低成本的前瞻性实验。
  - 详情 / Detail: Lighthouse 13.5.0 (Sep 18, 2026) adds an ard-schema audit grouped with llms.txt under agent discovery, in an experimental 'Agentic Browsing' category with a pass ratio rather than a 0–100 score. It looks for a pointer in robots.txt (Agentmap), a <link rel="ai-catalog"> or an HTTP Link header, falling back to /.well-known/ai-catalog.json, and validates the file against the ARD schema; no catalog means Not Applicable, schema errors fail. ARD is a proposal by authors from Google, Microsoft and Hugging Face; v0.91 renamed the file to ard.json, which 13.5 does not yet check. No ranking implication is stated.
